# Contributing to SOR

Thank you for considering a contribution.

## Before you start

SOR is at an early scaffolding stage. Check the README and existing issues first. For a substantial feature or architectural change, open an issue to discuss the approach before writing code.

## Ways to contribute

- Clarify requirements and propose designs.
- Improve documentation and examples.
- Add focused tests.
- Implement small, independently reviewable features.
- Review pull requests constructively.

## Development expectations

As implementation is added, each change should include the relevant tests and documentation. Do not claim a feature works unless it has been implemented and verified.

## Pull request process

1. Create a focused branch from `main`.
2. Keep changes small and explain the problem they solve.
3. Add or update tests for behavior changes.
4. Update documentation where needed.
5. Run the checks relevant to your change and include their results in the PR description.
6. Explain any security, compatibility, or operational impact.

Use clear commit messages and link related issues when applicable.

## Security-sensitive changes

Do not include real credentials, production data, exploit payloads, or sensitive logs in commits or issues. Follow [SECURITY.md](SECURITY.md) for vulnerability reports.

## Code of conduct

Be respectful, constructive, and welcoming. Critique ideas and code, not people.
